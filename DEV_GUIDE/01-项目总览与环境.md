## 3. Android SDK 安装记录（已执行）

安装位置：**`D:\workSofts\androidSDK`**（用户指定）

```bash
# 1) 下载 commandline-tools（143 MB）
curl -L -o D:\workSofts\androidSDK\cmdline-tools.zip \
  https://dl.google.com/android/repository/commandlinetools-win-13114758_latest.zip

# 2) 解压到 cmdline-tools/latest（sdkmanager 要求的固定层级）
#    zip 内含 cmdline-tools/ 目录，需上移一层 →
#    D:\workSofts\androidSDK\cmdline-tools\latest\bin\sdkmanager.bat

# 3) 用 JDK 21 运行 sdkmanager
set JAVA_HOME=D:\workSofts\jdk\jdk21
sdkmanager.bat --sdk_root="D:\workSofts\androidSDK" --licenses
sdkmanager.bat --sdk_root="D:\workSofts\androidSDK" --install ^
  "platform-tools" "platforms;android-37.0" "build-tools;37.0.0" "platforms;android-36"
```

**安装结果（已验证）**：

```
D:\workSofts\androidSDK\
├── build-tools/37.0.0/        140 MB   zipalign.exe + lib/apksigner.jar ✅
├── cmdline-tools/latest/      158 MB   sdkmanager v19.0 ✅
├── platform-tools/             17 MB   adb.exe ✅
├── platforms/android-36/                android.jar ✅
├── platforms/android-37.0/    279 MB   android.jar (43 MB) ✅
└── licenses/
总计约 729 MB（另有 cmdline-tools.zip 137 MB 原始包，可自行删除）
```

> 全流程耗时约 **20 分钟**（Google 源较慢，属正常现象）。

**踩坑记录（重要）**：
- 包名不是 `platforms;android-37`，而是 **`platforms;android-37.0`**（另有 37.1 / 37.2-beta）。直接用 `android-37` 会报 `Failed to find package`，并导致整批安装失败。
- `build-tools;37.0.0` 在稳定通道可用（最新稳定为 37.0.0）。
- sdkmanager 必须用 **JDK 17+** 运行，本机默认 JDK 1.7 会失败。
- 若 AGP 报找不到 `android-37` 平台，将 `gradle/libs.versions.toml` 的 `compileSdk` / `targetSdk` 改为 `"android-37.0"`。

## 4. 阻塞项与处理方案

### 4.1 ✅ 缺 `local.properties`（已创建）

`app/build.gradle` 用 `withInputStream` 直接读取，**文件不存在会直接构建失败**。已在仓库根创建（内容如下，密码见 4.2）：

```properties
sdk.dir=D:/workSofts/androidSDK
storeFile=D:/workSofts/keys/oktv.jks
keyAlias=oktv
storePassword=oktv2026
```

（金鑰密码与 keystore 密码共用 `storePassword`；`.gitignore` 已忽略 `*.properties` 与 `*.jks`，不会误提交。）

### 4.2 ✅ 缺签名 keystore（已生成）

已用 JDK 21 的 keytool 生成 **`D:\workSofts\keys\oktv.jks`**（RSA 2048，有效期 10000 天，alias `oktv`，store/keypass 均为 `oktv2026`）。

```powershell
& "D:\workSofts\jdk\jdk21\bin\keytool.exe" -genkeypair -v `
  -keystore D:\workSofts\keys\oktv.jks -keyalg RSA -keysize 2048 -validity 10000 `
  -alias oktv -storepass oktv2026 -keypass oktv2026 `
  -dname "CN=OKTV, OU=Dev, O=OKTV, L=, S=, C=CN"
```

SHA-256 指纹：`63:95:41:07:99:47:C2:54:E5:79:04:68:84:AD:64:82:5D:00:9A:51:8B:0F:5E:80:AE:EB:74:67:26:A4:37:B4`

> 注意：签名不同的 APK 无法覆盖安装 —— 这台机器上后续所有构建都请用这个 keystore，否则需要卸载重装。
> 若需换成你自己的签名，改 `local.properties` 三行即可（`.jks` 已被 .gitignore 忽略）。

### 4.3 ✅ Chaquopy Python 3.10（已装好）

`chaquo/build.gradle` 声明 `python { version = "3.10" }`，Chaquopy 会调用 `python -m venv` 建构建环境。
本机系统 Python 是 3.13.14，不满足；已按下列方式备好 **3.10.11**，装在 `D:\workSofts\python310`。

**官方 installer 在本机装不起来**（进程启动被安全策略拦，装完目录为空），改为 embeddable + 手工补模块：

```bash

# 2) 改 python310._pth，启用 site 与 Lib 路径
python310.zip
.
Lib
Lib\site-packages

import site

# 3) 装 pip
python.exe get-pip.py --no-warn-script-location

# 4) embeddable 缺 venv/ensurepip → 从 CPython 源码包取
tar -xzf Python-3.10.11.tgz Python-3.10.11/Lib/venv Python-3.10.11/Lib/ensurepip
cp -r Python-3.10.11/Lib/venv      D:/workSofts/python310/Lib/
cp -r Python-3.10.11/Lib/ensurepip D:/workSofts/python310/Lib/

# 5) venv 还缺 launcher
cp python.exe venvlauncher.exe

```

**构建时把该目录加进 PATH 即可，不必改 `chaquo/build.gradle`**：

```bash

```

**两个坑**：
- Git Bash 下 `python -m venv /tmp/xxx` 会被 **MSYS 路径转换**搞坏，必须用 Windows 原生路径
- 相对路径的 `python` 会被 WorkBuddy 的 python shim 劫持到 3.13 —— 校验时请用绝对路径
  `D:/workSofts/python310/python.exe`（误用 3.13 会让 venv 的 `pyvenv.cfg` 指向 3.13）

验证成功：Chaquopy 已生成 `chaquo/build/python/env/debug`（内含 cpython-310 的 pip）。

### 4.4 ✅ `lib-*.aar` —— 来源已查明，可本地编译产出

**它是什么**：`lib-*.aar` = **上游 `FongMi/media`（Media3 定制 fork）编译出的各模块 AAR**，
命名形如 `lib-common` / `lib-exoplayer` / `lib-ui` / `lib-decoder-ffmpeg` / `lib-mpvplayer` / `lib-ui-danmaku`。
（正因为模块名带 `lib-` 前缀，README 才写作「`lib-*.aar` 未納入 Git」。）

**关键事实（排查所得）**：

1. 需要的定制模块在 **`release-1.11.0-fongmi` 分支**，不在默认 `release` 分支：
   `libraries/mpvplayer`、`libraries/ui_danmaku`。
2. **不需要本地编译 ffmpeg / mpv**：仓库已提交预编译的
   `*/src/main/jniLibs/{arm64-v8a,armeabi-v7a}/*.so`（`libmpv.so`、`libavcodec.so`…），
   且 `decoder_ffmpeg/build.gradle.kts` 的 CMake 是**条件启用**的（头文件缺失即跳过 native 构建）。
3. jitpack 曾构建此分支失败，**原因只是 JDK**：jitpack 用 JDK 8 跑 Gradle 9.1.0 →
   `Gradle requires JVM 17 or later`。本机 JDK 21 不受影响。
4. 官方仓库及所有 fork（`chenmingquan/TV`、`zwzc/FongMiTV`、`ragehao/TvBox`…）的 `app/libs`
   **都没有**这批 AAR —— 不是遗漏，而是所有人都要自行产出。

**本地产出步骤**：

```bash
# 源码已就位于 D:\project_ai\oktv\fongmi-media（分支 release-1.11.0-fongmi）
# local.properties: sdk.dir=D:/workSofts/androidSDK
export JAVA_HOME="D:\\workSofts\\jdk\\jdk21"
export GRADLE_USER_HOME="D:\\project_ai\\oktv\\fongmi-media\\.gradle-home"
export GRADLE_OPTS="-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=23302 -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=23302"

cd /d/project_ai/oktv/fongmi-media
/d/workSofts/gradle-dist/gradle-9.1.0/bin/gradle.bat :lib-common:assembleRelease
# 同理编译 lib-exoplayer / lib-ui / lib-session / lib-decoder-ffmpeg /
#        lib-decoder-av1 / lib-mpvplayer / lib-ui-danmaku / lib-datasource-rtmp ...
```

产出的 AAR **不在常规的 `build/` 目录** —— 该 fork 把 `buildDir` 改成了 `buildout`，
真实路径是：

```
D:\project_ai\oktv\fongmi-media\libraries\<模块>\buildout\outputs\aar\lib-<模块>-release.aar
```

把这批 AAR 复制到 `app/libs/` 即可（已执行，见 [05 文档 §2](./05-遗留问题与推进状态.md)）。
`app/libs/.gitignore` 忽略 `lib-*.aar`；`app/build.gradle` 的 `fileTree(dir:"libs", include:["*.aar"])` 会自动引入。

> AGP 会**自动下载 NDK 29.0.14206865**（`decoder_ffmpeg` 的 `native-dependencies.properties` 指定），
> 约 2.5 GB，Google 源很慢，需耐心等待。
> `flatDir` AAR 之间不解析传递依赖，但只要**全部**放进 `app/libs`（同在 classpath 上）即可编译通过。

## 4.5 网络代理与 Gradle 缓存（本机必需配置，务必照做）

这台机器的三个实测结论：

1. **环境走 HTTP 代理**：`http_proxy / https_proxy = http://127.0.0.1:23302`
2. **Gradle 的 Java 下载器不读系统代理** → 必须显式传 JVM 参数，否则拉不到 distribution / 依赖
3. **`C:\Users\cmq11\.gradle` 被拒绝访问**（`FileNotFoundException: ...lock (拒绝访问。)`）
   → 必须把 `GRADLE_USER_HOME` 指到 D 盘

另外：`services.gradle.org` 会 **307 跳转到 github.com**；github 走代理可达（200），
但**清华 / 腾讯 Gradle 镜像站均不可达**（返回 000），不要改用镜像。
